# Voice Calendar Gemini Server

Small FastAPI service for extracting calendar events from natural language with Gemini.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Create `/home/admin/voice_calendar/.env` for deployment:

```bash
GEMINI_API_KEY=your-api-key
```

## Run

```bash
uvicorn main:app --reload
```

The API will be available at `http://127.0.0.1:8000`.

## Example

```bash
curl -X POST "http://127.0.0.1:8000/event?text=明天下午两点在肯德基吃饭"
```

## Database

The PostgreSQL schema file is `deploy/events.sql`.

Apply it with:

```bash
psql -d <database> -f deploy/events.sql
```

The schema enables `pg_trgm` for fuzzy text matching and creates an `events`
table:

- `id`: database-generated primary key. PostgreSQL fills this automatically when
  an insert omits it because the column is `BIGINT GENERATED BY DEFAULT AS
  IDENTITY`. Use `INSERT ... RETURNING id` when the application needs the new
  event id.
- `action`: parsed event operation, limited to `create`, `delete`, or `read`.
- `title`: required event title.
- `start_at` and `end_at`: event time range. `end_at` must be later than
  `start_at`.
- `location` and `description`: optional event details.
- `created_at`: timestamp for when the row was first inserted.
- `updated_at`: timestamp for the latest update. A trigger refreshes it on every
  row update.

Fuzzy matching indexes are created on `title`, `location`, and `description`.
For example:

```sql
SELECT *
FROM events
WHERE title % '开会'
ORDER BY similarity(title, '开会') DESC;
```

## Systemd Service

The service file is `deploy/voice_calendar.service` and expects the app to live in `/home/admin/voice_calendar`.

Install and start it with:

```bash
sudo cp deploy/voice_calendar.service /etc/systemd/system/voice_calendar.service
sudo systemctl daemon-reload
sudo systemctl enable --now voice_calendar
sudo systemctl status voice_calendar
```
